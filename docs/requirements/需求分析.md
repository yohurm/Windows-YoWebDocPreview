# YoDocPreview — 需求分析（v1）

> **版本：** v1（2026-08-27，首版定稿）  
> **参考架构：** `Yovo-Windows-ADBTools-tauri`（Rust core + Tauri 2 + SolidJS，core 零 Tauri 依赖）  
> **参考脚本库：** `yohu-harmonyos-docs/知识库/抓取脚本库`（`fetch_docs.py` / `check_updates.py`）  
> **定位声明：** 本项目将现有 Python 抓取脚本的能力**产品化为通用桌面应用**：在线文档浏览预览 + 一键导出 Markdown。**通用范围覆盖任意网页 URL**（内置通用网页适配器，正文提取 + 转换），并为结构化文档站（首个：华为开发者文档站）提供专用适配器以获得更高保真度。`yohu-harmonyos-docs` 仅作为脚本库与技术设计的参考，本项目**不接管该仓库**。

## 1. 项目概述

| 项 | 内容 |
|----|------|
| 名称 | **YoDocPreview**（产品名 `YoDocPreview`） |
| 标识 | `com.yohu.docpreview` |
| 平台 | Windows 10/11（x64） |
| 定位 | **通用在线文档阅读与导出工作台**：输入任意网页 URL（或结构化站点的 slug），在线拉取正文并渲染预览；支持单篇/批量导出为标准 Markdown 文档（含图片资源本地化） |
| 核心能力 | ① 任意网页在线预览（HTML 渲染）② HTML→Markdown 高保真转换（含通用网页正文提取）③ 批量抓取与更新检查 ④ 本地文档库管理 |
| 打包 | Rust + Tauri 2 单安装包（目标 ≤ 15 MB）；复用系统 WebView2；无需管理员权限 |

### 1.1 与参考脚本库的关系

| 脚本能力 | 本产品对应模块 |
|----------|----------------|
| `fetch_doc`（getDocumentById API 拉 HTML 正文） | 文档源适配器 → 在线预览 |
| `html_to_markdown`（14 步转换规则） | Rust 转换引擎 `yohu-md-convert`（规则全量移植） |
| `build_image_map`（图片 URL ↔ 本地 assets 映射） | 图片资源管理（导出时下载到本地） |
| `check_updates`（本地 vs 官方更新时间对比） | 更新检查模块 |
| `docs_to_update.json` / `manifest.json` | 本地文档库索引格式参考（自有 manifest 兼容此格式）；并支持导入外部 `docs_to_update.json` 作为批量任务清单 |

## 3. 产品目标与成功标准

| # | 目标 | 成功标准 |
|---|------|----------|
| G1 | **轻量化** | 安装包 ≤ 15 MB；复用系统 WebView2；无 Python/Node 运行时依赖（替代原脚本工作流） |
| G2 | **转换保真度** | 对样例集（≥ 50 篇真实文档）HTML→Markdown 转换结果与 `fetch_docs.py` 输出语义一致（标题/表格/callout/代码块/图片零丢失） |
| G3 | **通用性** | ① 任意网页 URL 可抓取预览并导出 Markdown（通用网页适配器 + 正文提取）；② 结构化文档站以 SourceAdapter trait 扩展，新增站点只需实现 trait + 转换规则配置，不改核心代码 |
| G4 | **批量效率** | 1000 篇文档批量抓取（并发 ≤ 4）可在 10 分钟内完成；进度实时可见、可取消、断点续跑 |
| G5 | 中文体验 | 全部 UI 中文；WebView2 原生 IME 零缺陷 |

## 4. 平台能力

### 4.1 工作台壳（Shell）

沿用 ADBTools v6 壳形态：

- 左侧：**导航栏**（在线预览 / 文档库 / 任务中心 / 设置）
- 右侧：单一内容区（当前模块主视图）
- 底部：状态栏（后台任务进度 + 版本号）

### 4.2 在线文档预览

- 输入方式：粘贴**任意网页 URL** / 结构化站点自动解析 catalog + slug / 手动输入 slug / 从历史记录选择
- 双通道拉取：
  - **通用网页通道**：HTTP GET 页面 HTML → 正文提取（Readability 式主内容抽取，剥离导航/广告/页脚噪声）→ 预览与转换
  - **专用适配器通道**：SourceAdapter 调用站点 API（华为站 = `POST getDocumentById`，含必需 Sec-Fetch 头）→ 取回 title / displayUpdateTime / HTML 正文
- 通道选择：URL 命中某专用适配器则优先走适配器；未命中自动回退通用网页通道（UI 提示当前通道）
- 预览渲染：WebView 内直接渲染净化后的 HTML（保留原始样式观感）；提供「Markdown 视图」切换（渲染转换结果）
- 元信息展示：标题、更新时间（适配器源）/ 来源 URL / 支持设备（device-type 映射 Phone/PC·2in1/Tablet/Wearable/TV，仅华为源）
- 失败处理：网络超时（15s）/ 接口异常 / 文档不存在（404）/ 正文提取失败分别给出明确错误态

### 4.3 HTML→Markdown 转换引擎（core，`yohu-md-convert`）

全量移植 `fetch_docs.py::html_to_markdown` 的规则，作为纯函数 crate（零 IO、零 Tauri 依赖、可单测）：

1. 表格单元格内 note 提取 → 移至最近表格前（callout 占位还原）
2. 代码块保护（`<pre>` 占位）→ 语言探测（ArkTS/ts/cpp/json/xml/bash/text）
3. note 提取 → `[!NOTE]/[!WARNING]/[!TIP]` callout
4. div 剥离、标题按官网层级映射（无标记 h4→h2，`[h2]`→h3，剔除标记、提取 device-type 行）
5. 表格转换（rowspan 展开、`\|` 转义、th 表头分隔行）
6. 行内格式（strong/b/a 链接）
7. 列表（ol 自动编号、ul、li 内多段落缩进折叠）
8. p/br/span 处理、图片标签转换（URL → 本地相对路径映射）
9. 实体解码（`< > & " &#39; &nbsp;`）
10. 相对链接补全为绝对 URL
11. 后处理（保护代码块前提下）：`<pid>` 类尖括号转义、`$r/$rawfile/%d$s` 转义、图片独立成行、前导空格清理、API 参考类目元数据间距
12. 文档头生成：`# 标题` + `更新时间：` + `来源：` + 支持设备行

**验收基线：** 以 yohu-harmonyos-docs 中 ≥ 50 篇已抓取文档为黄金样本，Rust 引擎输出与 Python 输出做结构化 diff（允许空白差异，禁止内容差异）。

### 4.4 文档源适配器（通用性核心）

```rust
#[async_trait]
trait SourceAdapter {
    fn id(&self) -> &str;                       // 如 "huawei-harmonyos"
    fn match_url(&self, url: &str) -> Option<DocRef>;   // URL → {catalog, slug}
    async fn fetch(&self, r: &DocRef) -> Result<RawDoc>; // → title/time/html
    fn converter_rules(&self) -> &ConverterRules;        // 站点特有转换配置
}
```

- **v1 内置适配器 ①（通用网页）：** `generic-web` —— 任意 HTTP(S) 页面，GET 抓取 + 正文提取 + 通用转换规则；无需注册即可兜底所有 URL
- **v1 内置适配器 ②（华为开发者文档）：** harmonyos-guides / harmonyos-references / harmonyos-faqs / best-practices / design-guides / harmonyos-releases 六个 catalog，映射规则同 `check_updates.py::catalog_for_manifest`（最长匹配优先）
- 后续站点（如其他厂商文档站）通过新增适配器扩展，UI 无需改动

### 4.5 本地文档库

- 库根目录用户可选（默认 `%LOCALAPPDATA%\YoDocPreview\library\`）
- 目录约定（参考现有知识库形态）：按用户选择的保存路径存放 `.md` + `assets/<doc-name>/` 图片目录 + 库级 `manifest.json` 索引
- manifest 条目：`file / url / slug / catalog / local_time / official_time / status`（格式兼容现有知识库 manifest，便于未来互操作；但本项目**不绑定、不接管**任何既有仓库）
- 支持导入外部清单文件（如 `docs_to_update.json`）作为批量任务来源

### 4.6 更新检查（批量）

- 移植 `check_updates.py` 逻辑（适用于带更新时间的适配器源）：遍历 manifest → 读本地 MD 头部 `更新时间：` → 查询官方 `displayUpdateTime` → 归一化对比（取前 19 字符）→ 产出待更新清单（NEW / UPDATE）
- 通用网页通道的条目无官方更新时间，更新检查跳过（可手动重新抓取覆盖）
- 进度持久化（断点续跑，对应 `.check_progress.json`）；限速可配；结果清单 UI 展示并支持勾选批量执行
- 404/失效文档单独标记，不阻塞整体流程

### 4.7 批量抓取与导出

- 单篇导出：预览页一键「导出 Markdown」→ 选保存位置（或直接写入库内规范路径）
- 批量导出：按更新清单/手动多选 → 并发抓取（默认并发 4，可配）→ 转换 → 写盘 + 图片下载到 `assets/<doc-name>/`
- 图片策略：**下载到本地**（png/jpg/jpeg/gif/svg），按出现顺序与已有资源对齐映射（同 `build_image_map`）；下载失败保留远程 URL 并告警
- 任务中心：进度条（n/total、速率、ETA）、失败明细、取消；写盘采用原子写（临时文件 + rename）
- 断点续跑：中断后重跑自动跳过已完成条目

### 4.8 设置

| 键 | 生效 | 默认 | 说明 |
|----|------|------|------|
| `library_root` | 重启 | `%LOCALAPPDATA%\YoDocPreview\library` | 文档库根目录 |
| `concurrency` | 下次任务 | 4 | 批量抓取并发数 |
| `request_timeout_sec` | 立即 | 15 | HTTP 超时 |
| `image_download` | 下次任务 | true | 导出时是否下载图片到本地 |
| `theme` | 立即 | system | 主题（system/light/dark） |

设置文件根固定：`%LOCALAPPDATA%\YoDocPreview\settings\`。

## 6. 非功能需求

| 项 | 要求 |
|----|------|
| 性能 | 冷启动 < 1.5s；单篇拉取+转换 < 2s；1000 篇批量 < 10min（并发 4） |
| 安全 | 不写系统目录/注册表；数据在 LocalAppData；HTTP 仅访问用户配置的文档源域名 |
| 可测 | 转换引擎 100% 纯函数可单测（cargo test + 黄金样本 diff）；适配器用录制响应 fixture 测试；UI 组件 Vitest |
| 合规 | 抓取行为与原脚本一致（仅文档正文 API，带常规浏览器头）；不做全站爬虫 |

| 层 | 技术 |
|----|------|

| 打包 | Tauri bundler（NSIS）+ WebView2 Evergreen 引导 |
| 测试 | cargo test（含黄金样本 diff）/ Vitest / 冒烟脚本 |

## 8. 架构约定（继承 ADBTools v6 ADR 精神）

- 依赖方向：`UI → @yohu/api → IPC ← commands ← core crates`；禁止 core 引用 Tauri
- 批量任务进度事件聚合推送（200ms 节流），禁逐条刷 IPC
- 长任务登记任务中心；退出序列 = cancel → 收敛 → 设置 flush
- 编辑/写盘即快照：原子写（临时文件 + rename），损坏备份 `.corrupt-<ts>`
- Tauri 2 事件名禁用点号（用 `/`）；invoke 命令名点分

---

## 9. 约束

- OS：Windows 10/11 x64；WebView2 Evergreen；无管理员权限
- 目标站点接口为非公开契约，需容错处理字段缺失/结构变化（`value`/`data` 双兼容，同脚本）
- 不引入 Playwright/无头浏览器；纯 HTTP API 拉取
- 单进程单安装包；文档源静态注册（不做插件热加载）

## 10. 已确认决策（2026-08-27 用户评审）

| # | 问题 | 结论 |
|---|------|------|
| D1 | 「通用」的范围 | **通用**：支持任意网页 URL（通用网页适配器兜底），结构化文档站以专用适配器增强 |
| D2 | 是否接管 yohu-harmonyos-docs 仓库 | **否**。该项目仅作为脚本库与技术设计的参考；本项目使用自有的文档库目录与 manifest 索引 |
| D3 | 是否支持任意普通网页 URL | **支持**（通用网页通道：GET 抓取 + 正文提取 + 转换） |
| D4 | 图片策略 | **都支持**：库内已有本地 assets 则按位置对齐映射复用；没有则下载到本地 |
| D5 | 登录态/Cookie | **不需要**（匿名 HTTP 拉取） |
| D6 | 导入外部 `docs_to_update.json` | **支持**（作为批量任务清单来源之一） |
