# YoDocPreview — 架构设计 v2

> **状态：** 设计定稿（增量升级，覆盖 v1；core 已部分落地，壳与 UI 按 v2 重组）  
> **日期：** 2026-08-28  
> **配套文档：** `docs/requirements/需求分析.md`（v1）· [ADR 索引](adr/README.md)（W1–W14）  
> **参考架构：** `Yovo-Windows-ADBTools-tauri` **as-built v6**（`docs/architecture/` 已拆分的 README / layers / ipc / workbench / adr 体系）——v2 吸收其 2026-08 重规划成果：**runtime ∥ protocol 宿主层、组合根壳、事件总线 + 批量分发、workbench 模块契约、ADR/as-built 文档体系**。

---

## 0. 一句话结论

在 v1「Rust 领域核心 + Tauri 2 壳 + SolidJS UI」基础上，按参考项目 v6 的升级模式做四件事：

1. **抽出 `yohu-runtime` 宿主层**（persist/os_paths，与 protocol 平行）——原子写、路径根从业务 crate 与壳中收口；
2. **壳重组为组合根模式**——`commands/` 分域薄命令、`events.rs` mpsc 事件总线（200ms 批量聚合）、`task_center.rs` 任务中心、退出序列、build.rs 身份校验；
3. **前端升级为 workbench 模块化工作台**——`@yohu/api` 门面 + `@yohu/workbench` 注册表 + `packages/modules/*` 模块包 + `apps/shell` 唯一组合点 + 依赖纪律脚本；
4. **文档体系升级**——v2 主文档 + `adr/` 决策目录；落地后按参考项目模式拆分为 as-built 文档地图。

**一句话：** runtime ∥ protocol → domain → { source ∥ md-convert } → library（capability 用例层）→ 壳（组合根）→ @yohu/api → workbench + modules。

### 2.2 依赖方向（唯一规则）

```text
UI（TS）   → @yohu/api → IPC ← commands（Rust）
                     ↑ 所有跨语言通信只经此一层
yohu-runtime ∥ yohu-protocol（互不依赖）
yohu-domain → yohu-protocol
yohu-md-convert（不依赖任何 yohu crate，纯函数；零站点知识）
yohu-md-huawei → md-convert + domain（华为文档方言；通用内核不得反向依赖）
yohu-source → yohu-runtime + protocol + domain
yohu-library → yohu-source + md-convert + md-huawei + domain + protocol + runtime   # capability（ADR-W13）
yohu-app = 唯一 Tauri crate（组合根）
@yohu/modules/* → @yohu/api + @yohu/ui（禁止依赖 @yohu/workbench、禁止模块互引、禁止 @tauri-apps/*）
```

禁止：core 引 Tauri；protocol 知道 domain；runtime 知道产品 wire 类型；模块互引；UI 写死版本号/身份。

### 2.3 核心设计原则（v1 五条继承 + v2 四条新增）

1. **core 零 Tauri**（继承）：转换引擎纯函数，`cargo test` 独立验证。
2. **转换在 core，渲染在 UI**（继承）：HTML→Markdown 只在 Rust 侧发生一次。
3. **适配器即策略**（继承）：SourceAdapter 后面对站点无感知。
4. **批量 IPC**（继承）：进度 200ms 聚合推送，禁逐条刷。
5. **写盘即快照**（继承）：一律原子写 + 损坏备份。
6. **宿主能力收口 runtime**（新，ADR-W10）：原子写/路径根只存在于 `yohu-runtime`；业务 crate 与壳不得自行拼 `%LOCALAPPDATA%`、不得自写 rename 逻辑。不建 `yohu-foundation` 杂烩 crate；不抽本项目用不到的 process 槽位。
7. **组合根壳**（新，ADR-W11）：壳 lib.rs 只做有序装配（设置探针 → paths → panic hook → 服务装配 → manage → 退出序列）；命令是反序列化→core→序列化的薄层；事件只经 `events` 总线发出，命令不直接 emit。
8. **library = capability 用例层**（新，ADR-W13）：v1 的「source 与 library 平级、壳层编排」与实现不符；v2 承认并固化现状——`export_one/batch/check/import` 是用例编排，归属 library；壳保持薄。
9. **workbench 模块契约**（新，ADR-W12）：静态注册（无插件热加载）；`apps/shell` 是唯一组合点；依赖纪律由脚本把守（`scripts/check-ui-deps.mjs`），不靠口头约定。

## 4. Rust 核心（core/）

### 4.1 yohu-protocol（分域拆分）

wire 类型零 IO 不变；文件按域拆分，防止单文件无限膨胀（对齐参考项目 protocol 分域）：

| 文件 | 内容 |
|------|------|
| `identity.rs` | 保持（PRODUCT_NAME/IDENTIFIER/DATA_DIR_NAME/version） |
| `event_names.rs` | 保持（`/` 分层常量 + EVENT_NAMES_ALL） |
| `doc.rs` | DocRef / FetchChannel / RawDoc / DocMeta / TreeNode（自 wire.rs 迁入） |
| `task.rs` | TaskState / TaskError / TaskProgress / TaskSummary / UpdateStatus |
| `library.rs` | LibraryEntry（snake_case 遗留兼容） |
| `settings.rs` | AppSettings wire 镜像（壳与 UI 快照载体；domain 保留键表与默认值单源） |
| `error.rs` | **`IpcError { code: String, message: String }`**——各 crate 自有 Error → 壳统一映射为此；不设统一 `YohuError`（继承参考项目决策） |
| `events.rs` | **`AppEvent`** 枚举（Progress/TaskDone/SettingsChanged/…，`#[serde(tag)]`）——事件载荷与信封单源；壳的 mpsc 总线只运这个 |

### 4.2 yohu-runtime（新增，ADR-W10）

与 `yohu-protocol` 平行、互不依赖；只含跨 capability 的本机能力：

| 模块 | 内容 | 迁移来源 |
|------|------|----------|
| `persist.rs` | `atomic_write` + `backup_corrupt`（`.tmp` rename；`.corrupt-<ts>`） | `yohu-library/src/atomic.rs` 原样迁出 |
| `os_paths.rs` | `app_data_root(product_dir_name)`（Windows `%LOCALAPPDATA%`，缺环境变量时明确报错而非静默 `.`）+ `open_path`（shell execute 收口） | 壳 `lib.rs::data_dir()` / `system_open_path` 拽出 |

**禁止：** 产品 wire 类型、URL、HTTP、Tauri。**不建：** process 模块（本项目无 sidecar 子进程需求，与 ADBTools 的 adb.exe 场景不同；未来需要时再加）。

### 4.3 yohu-domain（保持）

模块：`doc_ref` / `github` / `manifest` / `naming` / `time_cmp`（设置键表在 protocol）。仅两点微调：

- `settings.rs` 增补每键「来源/说明」描述，供设置页与 `settings/changed` 快照展示；
- `Effect` 语义表保持（LibraryRoot=Restart；Concurrency/ImageDownload=NextTask；RequestTimeoutSec/Theme=Immediate）。

### 4.4 yohu-source（修正四项）

| 项 | v2 处理 |
|----|---------|
| 死依赖 | Cargo.toml 移除 `yohu-md-convert`（源码零使用） |
| 通道头分离 | `HttpClient` 默认头只留中性（UA + Accept + Accept-Language）；华为 `Origin/Referer/Sec-Fetch-*` 移入 `HuaweiAdapter::fetch` 逐请求附加。generic-web 不得携带华为站头（当前缺陷：任意网页请求都带华为 Origin） |
| probe 下沉 | 新增 `source::probe_meta(http, doc_ref) -> Result<(String, Option<String>), SourceError>`：只取 title/displayUpdateTime。壳内 `probe_official`（20 行华为 API 复制）删除，改调此 API |
| LazyLock 纪律 | `extract.rs` 中循环/热路径的 `Regex::new` 全部提升为 `static LazyLock`（`text_len`/`strip_tags`/`best_dense_block` 每次调用都在编译正则） |

`SourceError` 保持自有错误 + `code()`；`adapter.rs` 注册表、`fetch_any` 编排、ADR-W1 自研评分器路线不变。

### 4.5 yohu-md-convert + yohu-md-huawei（ADR-W15）

- **`yohu-md-convert`**：公共内核。`html_to_markdown` 只用 `GenericDialect`。`base_url=Some` 补相对链接；`None` 保留相对路径，**不做**华为域名特例。
- **`yohu-md-huawei`**：华为开发者文档方言，实现 `ConvertDialect`（`[hN]` 标题、note、IconPic、`/consumer/cn/doc/`、`$r`、harmonyos-references）。黄金样本走本 crate。
- 调用方只经 `yohu-library::convert` 按 `source_id` 选引擎：华为 / GitHub 仓库 / 通用。禁止用 `base_url=None` 当站点开关。
- **`yohu-md-github`**：仓库 Markdown 方言（相对链接与 HTML `src`/`href` 补 blob/raw）。`GithubAdapter` 按 Contents 一层列目录、按 blob 分型拉文件，失败不降级 generic-web。

### 4.6 yohu-library（capability 用例层，ADR-W13）

**定位升级：** v1 称「yohu-source 与 yohu-library 平级，由壳层编排」；实现是 library 依赖 source+md-convert 并承担 `export_one` 编排。v2 固化为 capability 用例层（对齐参考项目 files/logsrv/mirror 的定位），壳只发号与转发。

| 组件 | 现状 | v2 动作 |
|------|------|---------|
| `store.rs` | manifest 加载/保存/upsert + `export_one` + tree + read_doc | 保持；错误改 `LibraryError` |
| `atomic.rs` | 原子写 | **迁出**至 `yohu-runtime::persist`，此处 re-export 一版过渡后删除 |
| `images.rs` | 映射 + 下载 | 保持（Content-Type 校验补齐） |
| `batch.rs` | 并发 worker + 取消 + 进度快照 | ① 错误 String → `LibraryError`；② **断点续跑**：`runs/<run_id>/state.json` 记录完成条目，同清单重跑跳过，完成态清理（v1 §5.4 兑现）；③ 进度产出改经回调通道交壳聚合 |
| `check.rs` | ❌ 无（逻辑散落壳内且串行） | **新增**：并发更新检查执行器——遍历 manifest → `source::probe_meta` → `time_cmp::classify` → 产出 NEW/UPDATE/NOT_FOUND 清单；`concurrency` 信号量并发（替代壳内逐条 await）；`CancellationToken` 可取消；进度回调（done/total/current）；断点 `.check_progress.json`（每 100 条持久化，`check.resume` 续跑）；generic-web 条目（catalog=="web"）跳过 |
| `import.rs` | ❌ 无 | **新增**：解析外部 `docs_to_update.json` → `Vec<BatchItem>`（`naming::is_safe_rel_path` 校验目标相对路径，防穿越） |
| 错误 | `Result<_, String>` | **`LibraryError`**（thiserror：Io / Source(SourceError) / Convert / Invalid / Cancelled）+ `code()`；壳映射 IpcError |

## 5. Tauri 壳（app/yohu-app，组合根）

### 5.1 模块划分（372 行单体 → 分域）

```text
app/yohu-app/src/
├── lib.rs            # 组合根：装配序 + invoke_handler + 退出序列（不含业务）
├── main.rs
├── state.rs          # AppState：registry/http/store/settings/runs/cache  + 事件 tx
├── paths.rs          # AppPaths：基于 yohu-runtime::app_data_root + DATA_DIR_NAME 拼装
│                     #   settings/ logs/ runs/ cache/ library/（重启冻结快照）
├── settings_store.rs # SettingsStore：load(宽容)/save_atomic/快照；settings.json 归此处
├── panic_hook.rs     # panic hook 写 logs/panic-<ts>.log（v1 §6 兑现）
├── events.rs         # 事件总线：mpsc::channel<AppEvent> + spawn_dispatcher；
│                     #   Progress 类可丢事件 200ms 聚合（最新快照），控制面必达（ADR-W11）
├── task_center.rs    # TaskCenter：run_id 发号、token 树、spawn batch/check、
│                     #   进度喂给总线、task/done 终态、runs 表管理、task.list 快照
└── commands/
    ├── mod.rs
    ├── doc.rs        # doc.fetch / doc.html / doc.convert / doc.history
    ├── library.rs    # library.root/tree/read/manifest/exportOne/importList
    ├── check.rs      # check.start / check.resume（后台任务，经 TaskCenter）
    ├── batch.rs      # batch.run / task.cancel / task.list
    ├── settings.rs   # settings.get / settings.set（set 后必发 settings/changed 全量快照）
    └── system.rs     # system.info / system.openPath（经 runtime::open_path）/ dialog.*
```

### 5.2 组合根装配序（对齐参考项目 setup 纪律）

```text
1) paths 探针：读 settings.json（宽容）→ libraryRoot 冻结快照 → AppPaths::resolve
2) panic_hook::install(logs_dir)          # 先于一切业务
3) 服务装配：HttpClient(设置超时/并发) + AdapterRegistry + LibraryStore + Cache(LRU=20)
4) events::spawn_dispatcher(rx, handle)   # 总线先行，命令才可能发事件
5) app.manage(AppState) + generate_handler![]
6) 退出序列（RunEvent::Exit）：root token cancel → 任务收敛 → settings flush
```

### 5.3 build.rs 身份校验（ADR-W14）

`build.rs` 校验 `tauri.conf.json` 的 `productName/version/identifier` 与 `yohu-protocol::identity` 常量一致，不一致直接 panic——身份单源从「约定」升级为「构建期把守」。UI 侧 `@yohu/api identity.ts` 由契约测试对齐，禁止写死。

### 5.4 tauri.conf.json 要点

`frontendDist` 由 `./ui-dist` 改为 `../../ui/apps/shell/dist`；`bundle` 启用 NSIS（perUser + WebView2 bootstrapper + SimpChinese）；CSP 按 v1 §6.1（`img-src https:` 放行远程图片，预览 HTML 经 DOMPurify 净化注入，ADR-W2）。

## 6. IPC 协议 v2

### 6.1 invoke 命令表（v1 §8.1 修订，★ 为 v2 新增/变更）

| 命令 | 参数 | 返回 | 说明 |
|------|------|------|------|
| `doc.fetch` / `doc.html` / `doc.convert` | 同 v1 | 同 v1 | 不变（大 payload 分离，ADR-W6） |
| ★ `doc.history` | — | `DocMeta[]` | LRU 快照（缓存已在壳内，补命令） |
| `library.root` / `tree` / `read` / `manifest` / `exportOne` | 同 v1 | 同 v1 | 错误改 IpcError |
| ★ `library.importList` | `{ path }` | `{ count, items }` | 经 `library::import`；返回待办条目进任务中心 |
| ★ `check.start` / `check.resume` | `{ limit? }` / — | `runId` | **后台任务**（v1 §8.1 设计、现实现为同步串行命令——回退到设计）；经 TaskCenter 发进度 |
| `batch.run` | `{ entries? \| urls? }` | `runId` | 支持导入清单条目（含 relDir）与裸 URL 两种输入 |
| ★ `task.list` | — | `TaskProgress[]` | 快照对账（事件丢失后重建） |
| `task.cancel` | `{ runId }` | — | 不变 |
| `settings.get` / `settings.set` | 同 v1 | 同 v1 | ★ set 后必发 `settings/changed`（当前缺失） |
| `system.info` / `system.openPath` | 同 v1 | 同 v1 | openPath 经 `runtime::open_path` |
| ★ `dialog.pickFolder` / `dialog.saveFile` | — | `path?` | tauri-plugin-dialog 封装；模块禁直连插件（v1 §8.1 设计兑现） |

错误统一：core 各 crate 自有 Error → 壳映射 **`IpcError { code, message }`**（来源见 protocol::error）；禁止 `String` 裸串跨 IPC。

### 6.2 事件表（语义不变，路径升级）

| 事件 | 载荷 | 语义 |
|------|------|------|
| `task/progress` | `TaskProgress` | **200ms 聚合最新快照，可丢**——由 `events.rs` 聚合器实现；当前「100ms 轮询逐 tick 直发」的模式废除（违反 ADR-W7） |
| `task/done` | `TaskSummary` | 终态必达 |
| `task/error` | `{ runId, error }` | 逐条失败明细（上限 200 条，超出聚合计数） |
| `settings/changed` | `{ key?, settings }` | 必达，全量快照 |

实现路径：core/壳各处只 `tx.send(AppEvent)`；`events::spawn_dispatcher` 统一消费——Progress 类进 200ms 聚合器（有界，满则覆盖），控制面 `emit` 必达。命令与 TaskCenter 不直接持有 AppHandle。

### 7.3 模块契约（对齐参考项目 ModuleDescriptor）

```typescript
// @yohu/workbench registry.ts —— 静态注册（ADR-v6-012 同款，无热加载）
interface ModuleDescriptor {
  id: string;                 // "preview" | "library" | "tasks"（与数据目录/事件命名一致）
  title: string;
  icon: IconName;             // @yohu/ui 图标名
  Component: Component<AppSession>;
}

// 壳注入的会话（模块不读壳 store、不自行 settings.get）
interface AppSession {
  identity: AppIdentity;      // 名称/版本（来自 @yohu/api identity，不写死）
  settings: () => AppSettings;        // 快照读取
  settingsChanged: (cb) => Unlisten;  // 订阅 settings/changed
}
```

- 模块 store 在模块内部创建；模块只依赖 `@yohu/api` + `@yohu/ui`。
- `scripts/check-ui-deps.mjs`（移植）：扫描 `packages/modules/*` 的 package.json 与源码 import，命中 `@yohu/workbench` / `@yohu/module-*` / `@tauri-apps/*` 即失败；接入 `pnpm lint`。
- `apps/shell` 之外的任何包出现 `@tauri-apps/*` 同样失败（Tauri 直连只允许在 `@yohu/api` 内）。

### 7.4 模块划分（功能与 v1 §7.3 一致）

| 模块 | id | 职责 |
|------|----|------|
| 在线预览 | `preview` | 主页空态打开台；详情为专栏 \| 网页或 Markdown（渲染/源码）\| 大纲 |
| 本地文档库 | `library` | YoTree 导航 / 阅读（YoDocPreview Markdown 模式）/ manifest 清单 / 导入外部清单 |
| 任务中心 | `tasks` | 任务卡片（进度/ETA/当前条目）/ 更新检查结果勾选批量执行 / 失败明细 / 取消 |

静态页 `app/yohu-app/ui-dist/index.html` 的既有功能（预览/导出/检查/批量）作为模块迁移基线，迁移完成后删除 ui-dist。

## 13. 风险与开放问题

| 风险 | 等级 | 应对 |
|------|------|------|
| check 并发化后华为接口限频 | 中 | 并发上限复用 `concurrency`（默认 4）；probe 失败重试一次；必要时加间隔参数 |
| @yohu/ui 外部依赖在本仓库的引入方式（path/git） | 中 | 优先 pnpm `file:` 相对路径（同 Gallery 目录并列）；不可行则 git 依赖 + 版本锁；组件缺项补进该库保持单源 |
| 前端 workspace 引入后 tauri dev/build 流程变化 | 低 | `beforeDevCommand: pnpm --filter shell dev`；`beforeBuildCommand: pnpm --filter shell build` |
| 黄金样本 diff 出现系统性偏差 | 中 | 豁免登记机制 + 逐条归因；`compare_all.py` 现存 3 篇真实样本先行验证管线 |
| runtime 抽取造成迁移期双写（library 与 runtime 各一份原子写） | 低 | 迁移即删（R1 内完成），不留 re-export 过渡层超过一个提交 |

**开放问题：**
1. `@yohu/workbench` 是否需要窗口三键自绘（参考项目 window-chrome）？建议 v2 维持系统标题栏，不加。
2. 检查结果是否需要持久化为「检查历史」？建议远期（数据表已在 cache/ 规划外，暂不做）。
3. library 模块是否提供目录整理（移动/重命名 + manifest 同步）？非需求范围，否决。
