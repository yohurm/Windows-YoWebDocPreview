# Windows-YoWebDocPreview 架构设计

> 版本：v1 草案 | 日期：2026-08-19 | 状态：评审中

## 1. 项目定位

**YoWebDocPreview** 是一个 Windows 桌面应用：把"网页文档 → 按知识库规范保存为 Markdown"产品化。输入任意网页 URL（普通文章、ChatGPT 分享链接、华为开发者文档），实时分栏预览（原文 | Markdown），按既定知识库规范导入本地。

- 技术栈：Tauri 2 + Rust core（tokio）+ SolidJS/Vite（对齐 Yovo-Windows-ADBTools v6 架构）
- 目标平台：Windows 10/11 x64，复用系统 WebView2
- 安装包目标：≤ 12 MB（对齐 Yovo G1 轻量化）
- 参考体系：`yovo-harmonyos-docs` 知识库（6 篇抓取规范 + fetch_docs.py 验证实现）

## 2. 需求分析（2026-08-19 已确认）

| 需求 | 定义 | 优先级 |
|---|---|---|
| 输入 | 任意网页 URL（普通文章 / ChatGPT 分享 / 华为开发者文档） | P0 |
| 抓取 | HTTP 直抓（reqwest）优先；动态页面按规范 04 降级 | P0 |
| 提取 | 通用网页 → Readability 正文提取；ChatGPT 分享 → devalue 解析；华为文档 → getDocumentById API | P0 |
| 转换 | HTML → Markdown：通用规则 + 站点专用规则叠加 | P0 |
| 预览 | 分栏：原文（净化的 HTML）\| Markdown 实时渲染，同步滚动 | P0 |
| 导入 | 按知识库规范：头部元数据 / 图片本地化 assets/{docName}/ / 目录规则 / manifest 可配 | P0 |
| 拓展 | SiteAdapter 适配器接口；批量/差异检测为预留能力 | P1 |
| 华为专项 | 华为文档 16 步完整转换流水线（对齐"严禁简化版"铁律） | P1 |

### 2.1 非目标（本期不做）

- 不内置浏览器引擎做渲染抓取（体积约束；HTTP 直抓已验证可行）
- 不做批量整站拉取（预留接口，二期按华为 catalog 流程实现）
- 不做登录态管理（分享页公开；华为 API 无需登录）
- 不做插件热加载（对齐 Yovo ADR-v6-012：静态组合）

## 3. 技术调研结论（2026-08-19 联网审查）

| 问题 | 结论 | 依据 |
|---|---|---|
| 桌面框架 | Tauri 2 | 用户已有 Yovo 项目验证；比 Electron 小 ~20 倍 |
| 通用正文提取 | `readability` crate（Mozilla 算法 Rust 移植） | 100 万+ 下载、32 反向依赖，最成熟；另有 readability-rust 备选 |
| HTML→Markdown 通用 | `htmd` crate（turndown.js 思路，可编程规则） | 47 万下载/月、450 stars、2026-04 活跃维护；Rust 生态最主流 |
| 华为文档转换 | 专用流水线：Rust 移植 fetch_docs.py 完整实现 | 规范 02 铁律"严禁简化版"；通用库无法覆盖 device-type/note callout/rowspan 等 |
| 剪藏类产品形态 | 正文提取 + 模板 + 存知识库（Obsidian Web Clipper 等） | 与本次架构方向一致 |
| 反爬 | reqwest 完整浏览器头 + cookie jar；分享页当前防护等级低（实测可行） | 规范：真实 UA + Sec-Fetch 头组 |

## 4. 总体架构

```
┌────────────────────────────────────────────────────────────┐
│ UI (SolidJS + Vite, pnpm monorepo)                         │
│ 输入URL → 分栏预览(原文|MD) → 编辑 → 导入设置 → 保存        │
└──────────────────────┬─────────────────────────────────────┘
                       │ Tauri IPC (invoke 命令 + 事件)
┌──────────────────────┴─────────────────────────────────────┐
│ app/yowebdoc-app — Tauri 2 壳（唯一引用 Tauri 的 crate）    │
│ commands 层仅做参数校验/转换，禁止业务逻辑                   │
└──────────────────────┬─────────────────────────────────────┘
                       │
┌──────────────────────┴─────────────────────────────────────┐
│ core/ — 零 Tauri 依赖（对齐 ADR-v6-005）                    │
│                                                             │
│ yoweb-protocol   ← wire 类型（serde DTO，无 IO）            │
│ yoweb-fetcher    ← HTTP 抓取：reqwest + UA + cookie jar     │
│ yoweb-extractor  ← SiteAdapter 接口 + 适配器注册表          │
│ yoweb-converter  ← HTML→MD：htmd 基础 + 站点规则叠加        │
│ yoweb-importer   ← 知识库规范落盘：头部/图片/manifest/原子写 │
└─────────────────────────────────────────────────────────────┘
```

### 4.1 分层原则（对齐 Yovo v6）

1. 依赖方向单向：`fetcher/extractor/converter/importer → protocol`；禁止 core 引用 Tauri
2. 纯函数域（extractor 的解析子模块、converter）无 I/O、无状态，可单测、可 fixture 回归
3. 副作用域（fetcher、importer）各自封装单一外部资源
4. 命令层薄：IPC 只做 DTO 转换，业务错误统一信封 `{ ok, error }` + 错误码
5. 模块静态组合：适配器注册进注册表（对齐 ADR-v6-012）

## 5. 核心数据流

```
URL
  → yoweb-fetcher.fetch(url)          → FetchedPage { html, final_url, requires_js }
  → extractor.registry().match(url)   → SiteAdapter
  → adapter.extract(html, url)        → Article { title, html_body, metadata, source_url }
  → converter.convert(article, rules) → ConvertedDoc { markdown, images[] }
  → UI 分栏实时预览：原文(html_body) | markdown
  → importer.save(converted, options) → ImportResult { file_path, manifest_entry }
```

### 5.1 DTO 契约（yoweb-protocol）

```rust
pub struct FetchedPage { pub html: String, pub final_url: String, pub requires_js: bool }
pub struct Article {
    pub title: String,
    pub html_body: String,        // 已提取的正文 HTML（预览左栏 + 转换输入）
    pub source_url: String,
    pub metadata: ArticleMeta,    // site_name/published_time/device_types 等可扩展
}
pub struct ConvertedDoc { pub markdown: String, pub images: Vec<RemoteImage> }
pub struct RemoteImage { pub url: String, pub alt: String, pub ext_hint: String }
pub struct ImportOptions {
    pub target_dir: String,       // 知识库根目录
    pub file_name: Option<String>,// 缺省 = title 清洗 + 时间戳
    pub localize_images: bool,    // 默认 true（03 规范）
    pub write_manifest: bool,     // 默认 false，可选
    pub manifest_group: Option<String>,
}
pub struct ImportResult { pub file_path: String, pub manifest_entry: Option<serde_json::Value> }
```

## 6. SiteAdapter 接口（拓展性核心）

```rust
pub trait SiteAdapter: Send + Sync {
    fn name(&self) -> &'static str;
    fn matches(&self, url: &Url) -> bool;
    async fn fetch(&self, url: &Url, fetcher: &dyn Fetcher) -> Result<FetchedPage, AppError>;
    fn extract(&self, html: &str, url: &Url) -> Result<Article, AppError>;
    fn conversion_rules(&self) -> ConversionRules;
}

pub struct AdapterRegistry { adapters: Vec<Box<dyn SiteAdapter>> }
impl AdapterRegistry {
    pub fn match_url(&self, url: &Url) -> &dyn SiteAdapter;  // 最长匹配优先
    pub fn register(&mut self, adapter: Box<dyn SiteAdapter>); // 静态组合
}
```

匹配规则：按 `matches()` 逐一判定，**最长/最具体优先**（对齐知识库规范 05 的"最长匹配优先"教训：华为 URL 同时含 doc 子串，必须先在通用适配器之前判定）。

## 7. 适配器详设

### 7.1 ChatGptAdapter（P0，已手工验证）

- 匹配：`chatgpt.com/share/{id}`
- 抓取：直接 HTTP GET（实测 curl + 浏览器 UA 可得完整 500KB HTML，无需登录、无需渲染）
- 解析（1:1 移植已验证逻辑，Rust 实现 `devalue.rs`）：
  1. `extract_stream_scripts(html)`：正则提取 `streamController.enqueue("<...>")` 的 JS 字符串字面量（可能多 chunk）
  2. `unescape_js_string(raw)`：按 JS 字面量规则反转义（`\"` `\\` `\n` `\uXXXX`），单字符扫描，禁用 eval
  3. `parse_stream_chunks(chunks)`：逐 chunk JSON.parse 后 concat → devalue 流数组
  4. `resolve_devalue(stream)`：键 `"_N"` → stream[N] 元素作键；值 ≥0 → 引用 stream[值]；**先注册占位再解析**（防循环引用）
  5. 定位含 `serverResponse` 的对象 → `data` → `title` / `create_time` / `model`
  6. `linear_conversation`（优先）或 `mapping` 链 → 过滤 user/assistant 消息
  7. 跳过隐藏 system 消息（`metadata.is_visually_hidden_from_conversation` / `rebase_developer_message`）
  8. `content.parts[]` join → 文本
- 转换规则：正文已是 Markdown，直接透传 + 头部生成
- 降级：解析失败 → `extract_visible_text(html)`（body 可见文本）→ 仍失败 → `PARSE_FAILED` + HTML 快照落盘

### 7.2 HuaweiDocAdapter（P1，华为专项）

- 匹配：`developer.huawei.com/consumer/cn/doc/{catalog}/...`
- 抓取：POST `getDocumentById` API（参考 fetch_docs.py：完整浏览器头组，`Sec-Fetch-*` 必须）；catalog 从 URL 判定
- 解析：API 返回 `content.content` 即完整正文 HTML
- 转换流水线（**Rust 移植 fetch_docs.py 完整实现，严禁简化**，对齐规范 02）：
  1. 提取表格内 note callout（平衡 div 计数）
  2. 剥离 `<div>`
  3. 保护代码块（占位符）
  4. 清除 `[h2]/[h3]/[h4]` 标记
  5. `<table>` → Markdown（表级解析、`<th\b` 词边界、rowspan 填充、表内 note 移出、行间空行修复）
  6. `<h1>-<h4>` → 标题（含 `device-type` 逐级提取 → `**支持设备：**`）
  7. `<img>` → 本地化引用入口
  8. `<ul>/<ol>` → 列表（li 内先折叠 p；多段落 2 空格续行；先替换 ul/ol 再清前导空格）
  9. `<p>` → 换行；10. 内联元素；11. 恢复代码块（含 highlight 噪声清理 + span/em 语法高亮清除）
  12. 恢复 note callout（Obsidian 格式 `> [!NOTE/TIP/WARNING]`）
  13. 清理残留标签；14. 实体解码；15. 相对链接绝对化
  16. 后处理（保护代码块前提下）：图片独立成行 / 行首空格清理（阈值 4）/ 连续空格压缩 / 特殊字符转义（`<pid>`、`$r(`、`%1$s`）/ API 元数据间距
- 头部：`# 标题` + `更新时间：` + `来源：URL` + `**支持设备：**`（h1 级别）
- 质量检查：规范 02 的 26 项清单对齐（子集内置）

### 7.3 GenericAdapter（P0，通用网页）

- 匹配：其余所有 URL（兜底）
- 抓取：HTTP GET + 编码检测（UTF-8/GBK 探测）
- 提取：`readability` crate（Mozilla 算法）→ `Article { title, html_body }`
- 转换：`htmd` 配置化（表格/列表/代码/内联/链接）+ 通用后处理（相对链接绝对化、图片独立成行、实体解码、空格清理）
- 降级：正文提取为空 → 检查 HTML 是否骨架屏（无正文长度阈值）→ `REQUIRES_JS` 提示（对齐规范 04："等正文可读"；一期提示用户，二期 WebView2 模式）

## 8. 转换层（yoweb-converter）

```
ConvertedDoc = Converter.convert(article, rules)
rules = ConversionRules {
    use_htmd: bool,                    // 通用转换是否启用（ChatGPT=false 透传）
    pipeline: Vec<Step>,               // 站点专用流水线步骤（华为=16 步全量）
    postprocess: Vec<PostStep>,        // 后处理（保护代码块前提下执行）
}
```

- 通用路径：htmd → 后处理 → 质量检查
- 华为路径：16 步流水线（§7.2）→ 质量检查
- 质量检查统一输出 `Vec<QualityIssue>`（残留标签 / 代码块缩进 / 表格分隔线 / 图片独立成行），UI 展示警告

## 9. 导入层（yoweb-importer，知识库规范映射）

| 知识库规范 | 实现 |
|---|---|
| 02 头部规范 | `# 标题` + `更新时间：` + `来源：URL`（华为 + `**支持设备：**`） |
| 03 图片规范 | 下载至 `assets/{docName}/file-{timestamp}.{ext}`；引用 `./assets/...`；路径空格 `%20` 编码；表格内图片独立单元格 |
| 05 目录规范 | 目标目录 + 子路径可配；manifest.json 条目可选生成（slug/file/url/title 字段，`file` 相对 manifest 所在目录） |
| 06 下线标记 | 预留：`更新时间：...（官网已下线）` 标记能力（二期批量用） |
| Yovo 原子写 | 临时文件 + rename；损坏备份 `.corrupt-<ts>` |

数据根：`%LOCALAPPDATA%\YovoWebDoc\`（设置 / 日志 / 失败 HTML 快照 `debug/fail-<ts>.html`）。

## 11. 错误模型

统一错误信封：`{ ok: false, error: { code, message } }`

| code | 含义 | 用户提示 |
|---|---|---|
| `NETWORK` | 连接失败/超时/非 200 | 网络错误，请检查网络后重试 |
| `BLOCKED` | 防护拦截（403/挑战页） | 被站点防护拦截；后续版本支持 Cookie 注入 |
| `INVALID_URL` | URL 格式非法 | 请粘贴完整网址 |
| `REQUIRES_JS` | 页面为 JS 渲染，无正文 | 该页面需要浏览器渲染，暂不支持（二期 WebView 模式） |
| `PARSE_FAILED` | 解析/转换失败（已降级仍失败） | 页面结构识别失败，已保存调试快照 |
| `SAVE_FAILED` | 路径/权限/写盘失败 | 保存失败：{原因} |

core 错误类型：`AppError`（thiserror，分类 + 消息），任一节点类型防御不 panic。

## 12. 设计决策（ADR 摘要）

| # | 决策 | 理由 |
|---|---|---|
| 001 | core 零 Tauri 依赖 | 对齐 Yovo ADR-v6-005；core 可独立测试 |
| 002 | HTTP 直抓，不引入浏览器内核 | 三类站点实测均可直抓；保住 ≤12MB 体积 |
| 003 | reqwest 而非 Tauri http 插件 | 官方插件有 body 解析已知 issue；core 内可测 |
| 004 | readability + htmd 为基础，不自研通用转换 | 生态最成熟；把精力放在站点专用规则 |
| 005 | 华为流水线 Rust 移植完整实现 | 规范 02 铁律"严禁简化版"（3,429 篇数据丢失教训） |
| 006 | 适配器最长匹配优先 | 规范 05 教训（catalog 判断顺序错误导致静默跳档） |
| 007 | 原文预览 HTML 净化 | 本地渲染不可信页面内容的安全底线 |
| 008 | 原子写 + 损坏备份 | 对齐 Yovo 编辑即快照 |
| 009 | 适配器静态注册，无热加载 | 对齐 Yovo ADR-v6-012 |

## 13. 二期路线（预留能力）

1. **华为批量拉取**：getCatalogTree 目录树 → 差异对比（官方时间 vs 本地 manifest）→ 断点续传 → 下线标记（对齐规范 01/05/06 全流程）
2. **WebView2 渲染模式**：动态页面按规范 04 流程（等"正文可读"→ 分段滚动 → 内容稳定采样）
3. **Cookie 注入**：BLOCKED 时 UI 提供 cf_clearance 等 cookie 粘贴入口
4. **多知识库配置**：多套目标目录 + 各自 manifest 规则

## 14. 构建与发布

- Rust：`cargo build --workspace` / `cargo test --workspace` / `cargo clippy --all-targets -- -D warnings`
- UI：`pnpm install` → `pnpm -C ui typecheck` → `pnpm -C ui build`
- 开发运行：`cargo tauri dev`（WebView2 + dev server）

- 构建在 Windows 侧执行（cargo 1.96.1 / pnpm 10.27 已确认）
