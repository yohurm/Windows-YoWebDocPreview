# 架构审查报告：通用在线文档预览工作台 (Windows-YoWebDocPreview)

> **依据规范**：`YoAgentDocs/instructions/prompts/tasks/architecture-review.md` 与 Windows 桌面分层规范（`rules/by-type/windows-desktop`、`rules/common/architecture.md`、`rules/by-type/ui-kit/file-srp.md`）。

---

## 一、审查范围与产品定位收敛

- **审查范围**：
  - Rust 后端层：`app/yohu-docpreview`（组合根壳、`commands/`、`state.rs`、`task_center.rs`）及 `core/` 关联 crate。
  - 前端 IPC 门面：`ui/packages/api`（类型契约 `types.ts`、命令映射 `commands.ts`）。
  - 前端工作台与视图：`ui/packages/workbench`（`App.tsx`）与 `ui/packages/modules/preview`（在线实时预览模块）。
- **产品核心定位**：
  - **通用实时在线文档预览与转换工具**（Web Doc Preview & Markdown Converter）。
  - 彻底剥离旧版残留的“本地知识库管理（Library）”、“批量爬取任务调度（Tasks）”以及“文档版本差异检测（Check）”等重型冗余能力。

### 3. 分层规范对齐（Desktop 架构: View → store → IPC → commands → domain）
- **现状**：UI View 直接调 `@yohu/api` invoke，在组件渲染函数体内直接做状态修改和错误捕获，没有 `store` 层承接会话投影与乐观 UX。
- **整改**：在 `preview` 模块建立规范的 `store.ts`，View 仅持有展现，把所有拉取、转换、导出、复制等事件交由 `store` 统一处理并投影到响应式状态中。

## 三、数据链路重设计（设计前 vs 设计后）

### 1. 文档导出链路 (Doc Export Flow)
- **设计前**：
  ```text
  [View] index.tsx 
    ↳ 点击导出 
    ↳ 越界调用 legacy 命令 libraryExportOne(url, catalog) 
    ↳ IPC invoke("library.exportOne") 
    ↳ commands::library::library_export 
    ↳ state.store.export_one 
    ↳ 强行在 %LOCALAPPDATA%/library 查找/写入 manifest.json 
    ↳ 返回写盘绝对路径
  ```
  *根因*：借用了旧版本地知识库的内部编排函数，产生虚假 manifest 依赖和伪知识库逻辑。
- **设计后**：
  ```text
  [View] PreviewMetaBar 
    ↳ 触发 store.exportDoc(customPath?) 
    ↳ [store] previewStore 处理加载态与路径推导 
    ↳ [IPC门面] @yohu/api::docExport(url, targetDir?) 
    ↳ [commands] commands::doc::doc_export (薄转发) 
    ↳ [core] yohu-source 拉取/缓存 + yohu-md-convert 纯文本转换 + yohu-runtime 原子落盘 
    ↳ 返回保存成功的 Path 
    ↳ [store] 更新 exportedPath 状态 
    ↳ [View] 渲染成功通知横幅与外部资源管理器定位按钮
  ```

### 2. 文档拉取、解析与大纲渲染链路 (Fetch & TOC Flow)
- **设计前**：
  ```text
  [View] index.tsx 
    ↳ handleFetch 内联 8 个 signal + 1 个 Promise.all 
    ↳ 散落正则计算 TOC，内联修改 DOM 字符串 
    ↳ 混合在 500 行的 UI 模板内
  ```
- **设计后**：
  ```text
  [View] PreviewHeader (输入并按回车) 
    ↳ store.fetchDoc(url) 
    ↳ [store] 乐观标记 loading = true，清除旧错误 
    ↳ [IPC门面] Promise.all([docFetch, docHtml, docConvert]) 
    ↳ [commands] commands::doc (doc_fetch / doc_html / doc_convert) 
    ↳ [core] 并行或缓存命中返回 DocMeta, RawHtml, Markdown 
    ↳ [store] 派发至 state (meta, rawHtml, markdownText) 
    ↳ [TOC Policy] 纯函数 parseToc(markdownText) 派生目录大纲树与注入锚点 
    ↳ [View] PreviewContent 响应式响应 store 投影完成高保真呈现
  ```

## 四、架构重构计划清单

1. **Rust 后端组合根重构**：
   - 清理 `app/yohu-docpreview/src/task_center.rs`。
   - 删除 `commands/batch.rs`、`commands/check.rs`、`commands/library.rs`。
   - 在 `commands/doc.rs` 增加精炼的 `doc_export` 命令（支持自定义目录或默认下载目录，支持图片下载配置）。
   - 在 `app/yohu-docpreview/src/lib.rs` 简化 `AppState` 与 invoke handlers 注册表，移除无用依赖。
2. **IPC 门面层重构 (`@yohu/api`)**：
   - 清理 `types.ts` 与 `commands.ts` 中的死类型与废弃命令。
   - 增加 `docExport` 契约，更新 `types.test.ts` 契约单源测试。
3. **工作台外壳解耦 (`@yohu/workbench`)**：
   - 提取 `SettingsView.tsx`，保持 `App.tsx` 专注桌面外壳与导航。
4. **实时在线预览模块重构 (`module-preview`)**：
   - 建立 `store.ts`、`toc.ts`、`components/PreviewHeader.tsx`、`components/PreviewMetaBar.tsx`、`components/PreviewContent.tsx`，重构 `index.tsx`。
5. **门禁与全流程构建验证**：
   - 检查 UI 依赖门禁、TypeScript 类型检查、Rust 测试套件、可执行文件构建与真机启动验证。
